Overview

This report documents the step-by-step pipeline used to compile a list of genetically engineered mouse model (GEMM) alleles that model human cancer-relevant mutations. The final output is a deduplicated spreadsheet where each row represents a unique mutant allele, resolved to the specific engineered mutation (e.g., Kras_G12D rather than just Kras).

STEP 1 Retrieve All Mutant Cancer Models from MMHCdb

MMHCdb's web interface uses a Solr search backend. The search page at /mtbwi/facetedSearch.do loads a JavaScript file (facet.js) that constructs queries to /mtbwi/solrQuery.do. By reverse-engineering this, we query the database programmatically.

Key discovery: The Solr endpoint only returns JSON via HTTP POST. GET requests return an HTML “Processing” wait page.

def fetch_mmhcdb():
    session = requests.Session()

    # Load the search page first to establish a session cookie (JSESSIONID).
    # Without this, the Solr endpoint rejects requests.
    session.get(f"{MMHCDB_URL}/facetedSearch.do", timeout=30)

    # Query parameters for the Solr backend:
    #   wt=json        → return JSON (not XML)
    #   q=*:*          → match all documents
    #   fq=mutant:true → filter to only genetically modified strains
    #                      (excludes wild-type tumor frequency records)
    #   facet=false    → skip facet counts, just return documents
    params = {
        "wt": "json", "q": "*:*", "fq": "mutant:true",
        "rows": 0, "start": 0, "facet": "false",
    }

    # First request with rows=0 to get the total count without data
    r = session.post(f"{MMHCDB_URL}/solrQuery.do", data=params, timeout=60)
    total = json.loads(r.text)["response"]["numFound"]
    # Result: 45,001 records

    # Paginate through all records in batches of 500
    all_docs = []
    for start in range(0, total, BATCH_SIZE):
        params["rows"] = BATCH_SIZE
        params["start"] = start
        r = session.post(f"{MMHCDB_URL}/solrQuery.do", data=params, timeout=120)
        docs = json.loads(r.text)["response"]["docs"]
        all_docs.extend(docs)
        time.sleep(0.3)  # rate limiting

    return all_docs

Allele extraction from markers

The strainMarker list mixes gene names, gene descriptions, and allele symbols. Allele symbols follow the pattern Gene<sup>allele_label</sup>. A regex extracts these:

def extract_alleles_from_markers(marker_list):
    alleles = []
    for item in marker_list:
        # Match pattern like "Kras<sup>tm4Tyj</sup>"
        # Group 1 = gene name (Kras)
        # Group 2 = allele label (tm4Tyj)
        match = re.match(r"^(\w+)<sup>(.+?)</sup>$", item)
        if match:
            gene = match.group(1)
            allele_label = match.group(2)
            alleles.append((gene, f"{gene}<{allele_label}>", allele_label))
    return alleles

STEP 3 Query MGI Allele Pages for Specific Mutations

The bulk report tells us what type of allele it is (knockout, targeted, conditional) but not which specific amino acid change was engineered. That lives on individual MGI allele detail pages.

For example, Kras<tm4Tyj> (MGI:2429948) has this on its detail page:

Mutation details: Glycine codon 12 was changed to aspartic acid (p.G12D) to encode an oncogenic form of the KRAS2 protein. A loxP site flanked STOP cassette was included upstream…

def fetch_mgi_mutation_details(unique_alleles):
    # For each unique allele with an MGI ID, fetch its detail page
    # and extract the "Mutation details" section via regex.
    for allele_symbol, mgi_id in alleles_needing_query:
        r = requests.get(f"{MGI_ALLELE_PAGE}/{mgi_id}", timeout=15)

        # The mutation details section sits between the "Mutation details" header
        # and the next major section (phenotypes, disease models, etc.)
        match = re.search(
            r"Mutation\s+details\s*:?\s*(?:&nbsp;)?\s*(.*?)"
            r"(?:<h\d|<div\s+class=\"detailSection|<section|id=\"phenoTable)",
            r.text, re.DOTALL
        )

        if match:
            desc_clean = re.sub(r"<[^>]+>", " ", match.group(1))  # strip HTML
            mutations = parse_mutation_from_description(desc_clean)

            # If no point mutation found, check for knockout/conditional keywords
            is_knockout = any(kw in desc_lower for kw in [
                "null allele", "disrupted", "replaced by neo", "deletion of"
            ]) and not mutations

        time.sleep(0.15)  # rate limit: ~7 requests/second

    # 1,289 pages queried, 1,062 returned mutation descriptions, 0 errors

Mutation parsing: four regex strategies

MGI describes mutations in varied formats. Four complementary strategies handle them:

def parse_mutation_from_description(desc):
    mutations = []

    # Strategy 1: HGVS protein notation
    # Matches: "p.G12D", "p.V600E", "p.R172H"
    prot_matches = re.findall(r"p\.([A-Z])(\d+)([A-Z])", desc)

    # Strategy 2: Natural language with position
    # Matches: "substitution of glutamic acid for valine at position 619"
    # Uses an amino acid name → single-letter lookup table
    pos_matches = re.findall(
        r"(?:substitution of )(\w+) (?:for )(\w+) at (?:position )(\d+)", desc)

    # Strategy 3: Codon change description
    # Matches: "glycine codon 12 was changed to aspartic acid"
    codon_matches = re.findall(
        r"(\w+) codon (\d+) was changed to (\w+)", desc)

    # Strategy 4: Standalone residue notation
    # Matches: "V600E", "G12D", "R172H" as standalone tokens
    # Filtered to positions < 5000 to avoid false positives
    standalone = re.findall(r"\b([A-Z])(\d{2,4})([A-Z])\b", desc)

    return mutations if mutations else None

STEP 4 Assign Allele Labels & Map to Human Equivalents

4a. Mouse allele labeling

Each allele is assigned a human-readable label based on the resolved mutation:

def resolve_allele_label(gene, allele_label, specific_mutations,
                          is_knockout, is_conditional, bulk_class):

    # Priority 1: Specific point mutation found
    # e.g. gene="Kras", mutations=["G12D"], conditional=True
    #      → "Kras_G12D_conditional"
    if specific_mutations:
        muts = "_".join(specific_mutations)
        return f"{gene}_{muts}_conditional" if is_conditional else f"{gene}_{muts}"

    # Priority 2: Knockout
    # e.g. gene="Trp53" → "Trp53_knockout"
    if is_knockout or bulk_class == "knockout":
        return f"{gene}_knockout"

    # Priority 3: Conditional (no specific mutation)
    # e.g. gene="Rb1" → "Rb1_conditional"
    if bulk_class == "conditional":
        return f"{gene}_conditional"

    # Priority 4: Other (gene trap, humanized)
    # Priority 5: Fallback to raw allele label
    # e.g. gene="Egfr", label="Wa5" → "Egfr_Wa5"
    return f"{gene}_{allele_label}"

def resolve_human_allele(gene, human_gene, specific_mutations, is_knockout, bulk_class):
    if specific_mutations:
        # Look up if mouse residue maps to a different human residue
        # Example: Trp53 R172H → "TP53 R175H"
        return f"{human_gene} {'/'.join(human_muts)}"

    if is_knockout:
        # Example: Trp53 knockout → "TP53 loss-of-function"
        return f"{human_gene} loss-of-function"

    if bulk_class == "conditional":
        return f"{human_gene} conditional loss-of-function"

STEP 5 Deduplicate to Unique Alleles

The 45,001 MMHCdb records are individual tumor observations — many strains appear multiple times with different tumor types. These are collapsed progressively:

45,001 MMHCdb records (individual tumor frequency observations)
↓ group by allele symbol across all strains
1,368 unique allele symbols
↓ resolve readable labels, merge duplicates
1,101 unique allele entries

During grouping, metadata is aggregated per allele:

  • Tumor types, organs, human cancer sites → collected into sets (all unique values kept)
  • Citations → first/primary publication retained
  • GEMM strain count → number of distinct strains carrying this allele

STEP 6 Clean-Up Filters

The final clean spreadsheet applies these filters to go from 1,101 → 909 entries:

6a. Remove “Other engineered” alleles (175 removed)

Alleles with MGI records but no resolved specific mutation and no clear knockout/conditional classification. Typically reporter constructs or conditional-ready cassettes not yet activated.

df = df[df['Allele Category'] != 'Other engineered']

6b. Remove gene trap alleles (6 removed)

Random insertional mutations, not targeted cancer-modeling alleles.

df = df[df['Allele Category'] != 'Gene trap']

6c. Remove chemically induced / spontaneous alleles without molecular descriptions (10 removed)

Alleles where no mutation details were available in MGI. The 38 retained alleles all have defined molecular lesions (e.g., Apc_Min with its characterized T→A transversion).

mask = (
    (df['Allele Category'] == 'Spontaneous / chemically induced') &
    (df['Molecular Description (MGI)'].isna())
)
df = df[~mask]

6d. One knockout per gene (0 additional removed — already unique)

If multiple knockout alleles existed for the same gene, keep the one used in the most GEMM strains.

ko = df[df['Allele Category'] == 'Knockout / null']
ko_dedup = ko.sort_values('Number of GEMM Strains Using This Allele', ascending=False) \
              .drop_duplicates(subset='Mouse Gene', keep='first')

6e. Clean duplicate residue annotations from point mutations (1 removed)

When the mutation description mentions both mouse and human residue positions (e.g., “R172H…corresponding to human R175H”), the parser may capture both. The human-equivalent residue is removed from the mouse label to avoid Trp53_R172H_R175H — producing Trp53_R172H instead.

Limitations

  1. Mutation parsing is heuristic — amino acid changes are extracted from free-text molecular descriptions using regex. Complex or unusual descriptions may be missed.
  2. Mouse-to-human residue mapping is curated, not exhaustive — only well-known cancer hotspot residue differences are covered. For less-studied genes, the mouse residue number is reported as-is.
  3. GMMID not included — the GMMID database was offline during data collection.
  4. Conditional alleles — some conditional-ready alleles appear as “conditional loss-of-function” but may produce different phenotypes depending on the Cre driver used.
  5. MMHCdb coverage — expertly curated but may not include every published GEMM, particularly very recent or non-English literature models.
